Guide

Get started

  • Install Bun. You only do this once.
  • Open a terminal and run the three lines below.
  • Open http://localhost:3000 in your browser.

Your site lives in the public/ folder. Change a file, save, and refresh the browser.

Add a page

Every file in public/ is a page. Create public/about.html:

Open localhost:3000/about. The header, footer and page frame are added for you, so a page only needs its own content. The <title> at the top is the name in the browser tab.

Pages in folders work too: public/blog/first-post.html opens at /blog/first-post.

Header and footer

Every page shares these files:

  • public/_header.html: your logo, links and the theme menu
  • public/_footer.html: the bottom of every page
  • public/_layout.html: the page frame around them

Save things

Here's a whole notes app. Create public/notes.html:

  • <loaf-form name="notes"> saves what you type. The name can be anything: recipes, contacts, ideas.
  • <loaf-list name="notes"> shows everything saved, newest first.
  • field="text" shows the input named text.

Notes stay after you refresh or restart.

More things a list can do

Put these inside a <loaf-list>:

Add thisWhat it does
<p edit="text"></p>shows the text; click it to change it
<input toggle="done">a checkbox that remembers
<button remove>Delete</button>deletes the item
<p field="created_at"></p>when it was saved

And these anywhere on the page:

Add thisWhat it does
<loaf-count name="notes"></loaf-count>how many there are
<loaf-empty name="notes">No notes yet.</loaf-empty>shows only when there are none

Put it online

Your site needs a host that runs Bun, like Railway or Fly.io. Use bun start as the start command.

If your site saves things, they're kept in the file loaf.db. Ask your host for a volume (a disk that stays) so saved data survives updates.

Remove what you don't need

  • The demo: delete public/demo.html and its link in _header.html.
  • The example in api/: delete api/hello.js.

For developers

Everything above works without this section.

Your own routes

Every .js file in api/ becomes a route. Export a function per method, or export default one function for all of them:

  • Files starting with _ are helpers, not routes.
  • Your routes win over the built-in data routes.
  • With bun dev, new files go live without a restart.
  • Import the database with import { db } from "../loaf/db.js". It's a bun:sqlite database.

Alpine and collection()

The loaf- elements are built on Alpine.js, which works in any page. x-data="collection('notes')" gives you items, add(), update(), remove(), loading, saving and error. Inside <loaf-list>, the current item is item, so Alpine attributes like :class="item.done && 'line-through'" work there too.

The data behind it

RequestWhat it does
GET /api/noteslist, newest first. Add ?limit=20&offset=40 for one page.
POST /api/notessave the JSON object in the body
GET /api/notes/5get one
PATCH /api/notes/5change the fields sent, null removes one
DELETE /api/notes/5delete it

Loaf blocks changes coming from other websites and caps uploads at 1 MB. To turn this data off entirely, set DATA=off in .env.

Layouts

  • A page is placed at <loaf-page></loaf-page> in the nearest _layout.html, so a folder can have its own.
  • A page that starts with its own <html> tag skips the layout.
  • For extra tags in one page's head, start the page with a <head> block.

Settings and AI

  • PORT (default 3000), DB (default loaf.db) and DATA=off can be set in .env.
  • Loaf's own code is in loaf/, with its version in loaf/VERSION. Leave it as it is so Loaf can be updated; your work goes in public/ and api/.
  • bun test runs the tests.
  • .claude/skills/ teaches AI assistants how Loaf works. Update the daisyUI one with curl -sL https://daisyui.com/llms.txt -o .claude/skills/daisyui/SKILL.md.
